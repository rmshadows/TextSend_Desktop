### 和 LocalSend 怎么选

这里比的是 [LocalSend](https://github.com/localsend/localsend)：附近设备互传文件。两边都只走局域网，都不经过云。

TextSend 把文字送进对面正在输入的那个框，同时进剪贴板。文件会落到「下载/TextSend」。LocalSend 把选中的文件直接交给对方，对方点接受后才开始传。

| | TextSend | LocalSend |
| --- | --- | --- |
| 文字打进当前输入框 | 主用途 | 有短消息，不往当前输入框里打 |
| 传文件 | 落到下载目录，可续传 | 主用途，接收前先点接受 |
| 谁能连上 | 扫码或 PIN；开了探测还要本机点允许 | 发现附近设备，接收时点接受 |
| 系统 | Android、电脑、uTools。iOS 还在做 | Android、iOS、Windows、macOS、Linux |
| 线上怎么保护 | 连上之后是 AES-GCM。点允许时两边做临时密钥交换，并显示同一串核对码 | 每台设备一张自己的证书，整段走 HTTPS |

要打字上屏，用 TextSend。要在各系统之间丢文件、还要 iPhone，用 LocalSend。

### 界面功能

大窗是主界面；「置顶小窗」是紧凑窗（Esc 回大窗）。文件相关操作在大窗。

**文字**

- 点「发送」或 Ctrl+Enter：输入框有焦点时发文字。对面进当前焦点，同时进剪贴板。
- 客户端：粘贴 `ts://…` 连接串后点连接。端口可省略，默认 54300。

**文件**

- 拖入或「浏览」加入待发列表，**选中后再发**。一次最多 50 个扁文件。主界面不收文件夹。
- 「浏览」左键 Java 对话框（可把文件拖进对话框，打开该文件所在文件夹）；右键用系统文件选择框。Shift+左键打勾选 **多个文件夹**（按相对路径重建，不是同步；`.logger` 这类隐藏目录会带上）。也可把文件夹拖进窗口。
- 对面落到系统「下载/TextSend」，不弹保存框；重名自动 `name (1).ext`。大窗待发区点「下载目录」（或列表右键）用资源管理器打开本机该文件夹。
- 发送中仍可往列表加文件，会接着发。底栏有进度、实时速度和「取消」（发/收都能停）。
- 发文件夹时进度显示 `3/40` 和第几个文件的百分比。
- 断线可续传（认文件头+尾哈希；对不上则从头）。发送方点取消会留下半截，再发同一文件接着传；接收方点取消才删半截。
- 多台已连接设备会全发，超过 1 台时提示数量；同一文件并行发给各端。
- Android **5.0.12**、uTools **5.0.11** 已支持收发文件/文件夹。旧 uTools 5.0.7 没有 `"file"`，发给它会立刻提示对端不支持。

**图片**

- 收到的图片 ≤20MB 写入系统剪贴板（不自动 Ctrl+V）；更大或解码失败则落地。
- 本机 Ctrl+V 图片先出现在输入区预览，可「查看大图」；Backspace 或「清除」去掉预览；点「发送」才传。

服务端：

- 启动：左键最多 1 人并开二维码；中键最多 N 人（N 在「设置」，默认 7）；右键启动但不弹二维码。
- 「设置」：局域网探测、探测口、中键上限、二维码失焦关闭、授权限流/冷却/黑名单。
- 探测打开后客户端可请求临时授权；主界面「待授权」列表允许/拒绝/拉黑（不弹窗）。两边先显示同一串核对码，对得上再允许；一次性密钥不进网络包。「已连接」可踢下线。
- 切换：切换到客户端模式。

客户端：

- 连接：粘贴完整连接串 `ts://IP/k...`（或 `ts://IP:端口/k...`），不要只填 IP。
- 「设置」可开局域网探测；点设备会请求服务端授权（免输 PIN，须对方允许）。
- 切换：切换到服务端模式。

### 原理：发现设备，再点一下授权

平时不用开探测。扫二维码或粘贴 `ts://…` 走的是 TCP 会话，和下面这套 UDP 无关。

打开「局域网探测」之后，发现设备和正式连上是两条路，端口号默认相同（54300），协议不同：

| | 发现设备 | 点设备授权 | 连上之后传文字/文件 |
| --- | --- | --- | --- |
| 协议 | UDP | 先 TCP，TCP 失败才改 UDP | TCP |
| 端口 | 探测口，默认跟着主界面那个连接口 | 对方广播里写的 TCP 口 | 同一个 TCP 口 |
| 包 | `TSQ1` 问、`TSD1` 答 | `TSA1` | 帧头 `TS`，正文 AES-GCM |

防火墙若只放行了 TCP 54300，手机能扫码连上，但列表里看不到设备。探测还要放行**同一个端口号的 UDP**。

探测默认关。开了之后大约每 1 秒做两件事（IPv4，发到 `255.255.255.255` 和各网卡的子网广播地址）：

1. **主动广播**（设置里默认开）：本机如果正在当服务端，广播一包 `TSD1`，告诉别人「我在这个 TCP 口等连接」。关掉之后不再定时喊，别人来问仍会答。
2. **探测**：无论是不是服务端，都广播一包 `TSQ1`。收到的服务端用单播回一包 `TSD1`（回到提问者的那个 UDP 地址和端口，不再广播）。

本机发出去的包、以及来源地址是自己网卡的包，直接丢掉。列表里超过约 2.5 秒没再收到 `TSD1` 的设备会消失（进程被强杀时来不及发下线包）。同一个 8 字节实例号出现在多个 IP 上，界面会标成「可能是同一设备」（一个进程挂了多块网卡）。

「有连接时关闭探测」默认开：已经有人连上，或自己作为客户端连上了，就停止广播和探测，列表清空。UDP 套接字留着，后面的授权包还能进来。

#### 探测包 `TSQ1`（问一句「谁在」）

固定 6 字节，没有设备名，没有端口，没有密钥：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII `TSQ1` |
| 4 | 1 | 版本 `0x01` |
| 5 | 1 | 保留，现在是 `0x00` |

十六进制就是 `54 53 51 31 01 00`。

#### 在线包 `TSD1`（回答「我在，请连这个 TCP 口」）

只带正在监听的 TCP 端口、设备名、8 字节实例号。没有 PIN，没有密钥。设备名 UTF-8，最长 48 字节，总长 = 16 + 名字字节数。

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII `TSD1` |
| 4 | 1 | 版本 `0x01` |
| 5 | 2 | TCP 端口，大端。54300 = `0xD41C` |
| 7 | 1 | 设备名字节数 |
| 8 | n | 设备名 |
| 8+n | 8 | 本次进程随机的实例号 |

名字是 `pc`、端口 54300、实例号 `01 02 03 04 05 06 07 08` 时，整包是：

```text
54 53 44 31 01 d4 1c 02 70 63 01 02 03 04 05 06 07 08
T  S  D  1  版本 端口54300 名长 「pc」        实例号
```

#### 点设备之后：授权包 `TSA1`

列表上点一台设备，并不是马上把 PIN 发出去。客户端连到 `TSD1` 里的那个 TCP 口，一上来先写授权包。服务端接进来先等最多 400 毫秒看前 4 个字节：是 `TSA1` 就当成授权，不占连接名额；超时没有字节，才按普通会话处理（服务端先发 HELLO）。TCP 没走通、而且不是拒绝也不是取消时，同一份字节再从探测口 UDP 发一次。

授权版本现在是 `0x02`。公共头 6 字节：`TSA1` + 版本 `0x02` + 类型。类型：

| 类型 | 值 | 谁发 | 后面还有什么 |
| --- | --- | --- | --- |
| REQUEST | `0x01` | 客户端 | 1 字节名长、设备名（≤48）、16 字节 nonce、65 字节临时公钥（未压缩 P-256，首字节 `0x04`） |
| PENDING | `0x04` | 服务端 | 同一个 nonce、服务端自己的 65 字节临时公钥 |
| GRANT | `0x02` | 服务端点允许 | 同一个 nonce、服务端公钥、2 字节 TCP 口、4 字节过期时间（Unix 秒，大端） |
| DENY | `0x03` | 服务端拒绝 / 拉黑 / 限流 | 同一个 nonce、2 字节等待秒数。`0xFFFF` 是拉黑或直接拒绝，其它数字是冷却还剩几秒 |
| CANCEL | `0x05` | 客户端再点同一台 | 同一个 nonce。服务端只删掉这一条待授权，不记冷却 |

两边各自拿对方公钥做 ECDH（P-256），再用 HKDF 推出 32 字节一次性密钥。HKDF 的盐是这次的 nonce，info 是 ASCII `textsend-v1|lan-auth`。这 32 字节不进任何包。GRANT 里只有公钥和端口，客户端拿到后自己算出同一把密钥，再按普通 `ts://` 去连，60 秒内有效。

核对码是 `SHA-256(客户端公钥 ‖ 服务端公钥 ‖ nonce)` 的前 4 字节，显示成 `ABCD-EF01`。它出现在服务端待授权那一行，也留在客户端那台设备的按钮上，直到允许、拒绝、超时或取消。两台屏幕上这串不一致，就不要点允许。

再点正在等的那一台，会在原来的 TCP 上写出 `CANCEL` 并半关写方向，让对方看到结束；探测套接字若还在，也会再发一份 UDP `CANCEL`。

 ### 使用方法（旧版本）

注意：客户端和服务端要在同个局域网（比如同一个Wifi）

打开TextSend电脑服务端，配置防火墙，允许外来流量、同意访问网络。

选择服务端口，默认54300端口，可以直接按回车跳过。

![setport](https://images.gitee.com/uploads/images/2020/0711/153035_c4690e50_7423713.png "屏幕截图.png")

进入主界面，一个小悬浮框。点击启动，启动Server，手机才能连接。发送是用来向手机发送文字的，发送到手机的文字保存在手机的剪贴板上。

![main](https://images.gitee.com/uploads/images/2021/0903/230318_b2442988_7423713.png "屏幕截图.png")

这时会跳出二维码窗口（可能是用浏览器打开的），手机客户端可以扫描二维码直接连接

![QR Code](https://images.gitee.com/uploads/images/2021/0903/230402_b574cc43_7423713.png "屏幕截图.png")



这是客户端界面

![client](https://images.gitee.com/uploads/images/2021/0903/230436_de1afbb4_7423713.png "屏幕截图.png")

**注意** ：协议 v1 起可传文字和文件。文件落到「下载/TextSend」，不弹保存框。强烈建议在家庭等相对安全的局域网内使用。

连接好手机后，打开一个Word文档，鼠标在Word文本输入的地方点一下，保证文本输入区域是焦点。这样手机发过来的文字会直接打在Word文档中。如果不小心失去焦点，没输入成功。你只需要右击粘贴就是，因为手机发送的文字也是存在电脑剪贴板上的。手机（5.0.12）可以收文件，落到「下载/TextSend」；手机发出的图片也落地，不进电脑剪贴板。
